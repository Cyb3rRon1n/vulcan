- [x] **Homepage tile descriptions, and a real, significant Homepage bug fixed along the way** — every tile now shows a real one-line description (gethomepage.dev's own `description:` field), not just an icon and a name. Found while verifying it against a real running Homepage container: the current image outright refuses every request without a real `HOMEPAGE_ALLOWED_HOSTS` value (a relatively recent Homepage/Next.js security requirement) - meaning Homepage was completely unreachable on a fresh install before this fix, not a cosmetic gap. Fixed by computing the real allowed-hosts list (`localhost:3000`, the detected LAN IP, and the routed Traefik hostname when active) and threading it into the compose template. Verified end-to-end against a real container: came up and answered `200` instead of refusing the request, and every tile's real description round-tripped through the running app's own `/api/services` endpoint.
- [x] **Port-conflict diagnostics naming a real cause, not just a port number** — the exact real incident the user hit (refused start on port 8080, no way to tell it was their own orphaned containers) now gets an actual answer: `identify_port_owner()` distinguishes "your own orphaned containers - run `vulcan uninstall`" from "an unrelated container" from "not a Docker container at all," using only Docker (no new tool dependency). Found and corrected a real wrong assumption before shipping: `docker ps --filter publish=<port>` looked like the right tool and produced a real false positive when tested - parsing the real `{{.Ports}}` field is what's actually reliable. Verified against two real containers: an unrelated one (identified by name/image) and one carrying the exact label a genuine orphaned Vulcan deployment would have (identified as "your own," with the real fix named).
- [x] **Per-tier composition shown in both the TUI and CLI** — a real gap the user hit directly during a dry-run install (neither interface said what a tier actually contained, only its name). `tier_description()` generates the text from each tier's real `ServiceDefinition` list rather than hand-written copy, wired in as CLI print lines and as real TUI tooltips. Found and fixed two real Textual ordering bugs along the way: a naive new row broke the screen's real, already-documented height budget; the fix (reusing the existing `#tier-error` line) then exposed a second issue where Textual's auto-focus-on-mount immediately cleared it, fixed by keeping the RadioSet's own tooltip in sync too.
- [x] **Decluttarr (download queue cleanup)** — researched the real "media agent" request first rather than building one: quality/subtitles was already Recyclarr's/Bazarr's job, and a mature real tool ecosystem exists for the genuine gap (stalled/failed downloads). Picked `ghcr.io/manimatter/decluttarr` (confirmed actively maintained over similarly-named forks), a 20th real service, tier-agnostic and optional like Recyclarr. Real starter `config.yaml` generated with correct `base_url`s but placeholder API keys (Decluttarr's config has no env-var substitution mechanism, confirmed by reading its real current schema, not an earlier AI-summarized doc fetch that got this wrong), defaulting to `test_run: true` (matching upstream's own recommended default), never overwritten on a regenerate. Correctly targets `gluetun` as qBittorrent's hostname when Gluetun owns its network namespace. Verified against the real image: started cleanly, correctly announced test mode active, attempted a real connection to the exact generated URL.
- [x] **Tailscale (private remote access) and Cloudflare DNS-01 (real Let's Encrypt certificates)** — a 19th real service (Tailscale, custom-mode only, `network_mode: host` so every host-published port becomes tailnet-reachable automatically with zero route-approval step) plus a Traefik TLS modifier (Cloudflare DNS-01, opt-in, `--cloudflare-dns`/`--cloudflare-email`), not a 20th service. Real, well-documented Traefik gotcha handled up front: `acme.json` pre-created at mode `600` (only if missing, never overwriting real cert data). Found and fixed a second real pre-existing bug along the way: `render_env()`/`write_stack()`'s Gluetun checks used `config.enabled_optional` directly, which custom mode never populates - a custom-mode stack with Gluetun enabled silently generated a compose file needing VPN credentials `.env` never defined, with no warning either. Verified against real Docker: the real `tailscale/tailscale` image started cleanly and failed with a genuine `invalid key` error (not a config error) using a placeholder auth key; real `traefik:latest` accepted every Cloudflare DNS-01 flag and stayed running.

## Next

- [ ] **A real end-to-end run on actual ARM64 hardware.** The static audit above is done and clean, but nothing in this project's history has actually installed and run on real ARM hardware — everything real-verified so far has been on one x86_64 Fedora machine. The single biggest remaining gap.
- [ ] **`detect_cpu()`'s `cpu_model` parsing is x86-only.** It looks for a `"model name"` line in `/proc/cpuinfo`; real ARM64 Linux typically exposes `CPU implementer`/`CPU part` instead, so `cpu_model` will likely read as unknown on real ARM hardware. Not a crash (already handled as "not present"), but a known display gap to fix once real ARM hardware is available to verify against.
- [ ] **`detect_gpu()` has no ARM SBC-style detection** (e.g. a Raspberry Pi's VideoCore/V4L2 stack) — falls back cleanly to software-only Jellyfin transcoding today, but hardware transcoding on real ARM SBCs was never in scope.
- [ ] **Watch for a real stable Readarr release.** Currently pinned to `0.4.19-nightly` (over a year stale as of this writing) because it's the only tag LinuxServer publishes that actually works — re-pin once a real `:latest`-equivalent exists.
- [ ] **A shared constant for the Traefik/Homepage web-facing service set.** Both currently maintain their own independent per-service condition list; flagged as a real follow-up when Homepage pre-seeding shipped, never folded in since neither slice needed it enough to justify an unrelated template refactor.
- [ ] **Remove `presets/`.** Empty, unreferenced directory left over from the original scaffold at the repo root — not wired to anything.
- [ ] **Port-conflict override, not just diagnosis.** Naming the real cause (shipped) is step one of three originally scoped; still open: letting the user remap a conflicting service's host port at generate time instead of only refusing, and offering to run `vulcan uninstall` automatically when the identified cause is genuinely the user's own orphaned stack (the diagnostic already tells them to do it manually - automating the safe case is the natural next step).

## Deliberately out of scope

Recorded so these don't get relitigated as gaps later — each was considered and rejected for a real, documented reason.

- **Let's Encrypt / ACME automation for DNS providers other than Cloudflare.** The original "don't hardcode one DNS provider among dozens" reasoning held until a user specifically named Cloudflare - Cloudflare DNS-01 shipped (see above), but every other DNS provider Traefik/Lego support (Route53, DigitalOcean, etc.) stays genuinely out of scope until someone names one of those too. HTTP-01 (needs a port-forwarded public domain) also stays unimplemented - DNS-01 covers the real request that came in.
- **Traefik routing for qBittorrent when Gluetun is enabled.** Not a bug — a real Docker networking limitation: a container using `network_mode: "service:gluetun"` has no network identity of its own for Traefik's Docker provider to discover. Explained via a `write_stack()` warning instead of silently generating labels that would never route.
- **A daemon or scheduled mode.** Every command is on-demand (`./install`, `vulcan update`/`pull`/`backup`/etc.), matching the project's "observe, then act" design principle — Heavy tier's Watchtower already covers continuous background updates for anyone who wants that specific behavior.
